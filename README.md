# ssh-bruteforce-detection
Python rule that detects SSH brute-force attacks in Linux auth.log using a 5-minute sliding window. Includes a synthetic sample log, test output and a negative test
# SSH Brute-Force Detection

A Python detection rule that finds SSH brute-force attempts in a Linux `auth.log`. It was built as the first detection rule for a simulated client (GreenField Farmers Co-op) during a cybersecurity internship project.

> **Note:** All logs in this repo are synthetic, generated by `gen_log.py`. No real system or real IPs were used.

## How it works

1. Reads the log and parses `Failed password` events from `sshd`. It handles both the normal and the `invalid user` line formats.
2. Groups failed attempts by source IP.
3. Uses a sliding 5-minute window to find the highest number of failures per IP.
4. Flags any IP with 5 or more failures inside one window (`THRESHOLD`, which can be tuned).
5. Prints the top suspicious IP, the attempt count, the time range, and a table of all IPs.

## Usage

```bash
python detect_bruteforce.py auth.log
```

Generate the sample log yourself:

```bash
python gen_log.py > auth.log
```

Requires Python 3 only. There are no external libraries.

## Negative test

`slow_test.log` contains one IP failing once every 3 minutes (6 failures in total), so it never reaches 5 failures inside any 5-minute window.

```bash
python detect_bruteforce.py slow_test.log
```

Output: `No brute-force activity detected.`

## Limitations

- The threshold (5 failures in 5 minutes) is a starting value and should be tuned to the real environment's normal traffic.
- Timestamps in `auth.log` have no year, so the script assumes `YEAR = 2026`. Logs that span New Year need an adjustment.
- It only covers password failures over SSH. It does not detect key-based or distributed (many-IP) attacks.
